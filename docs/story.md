# 一台 iPad Air 1 的副屏复活记

> 记录这条链路是怎么被一点点试出来的：哪些路是死路、哪些是坑、为什么最后落在现在这套方案上。

## 起因

手边有一台 iPad Air 1（iPad4,1），系统停在 iOS 12.5.8。它跑不动新 App，但屏幕还行——2048×1536 的 4:3 面板，拿来看文档、放参考图、挂聊天窗口都挺好。

于是想让它当 Mac 的第二块屏。然后依次撞墙：

### 死路一：Sidecar

官方「随航」不支持 iPad Air 1，也不支持 iOS 12。系统层面直接不给你选项，没有绕过的空间。

### 死路二：Duet Display

Duet 的老版本曾经支持 iOS 12，但当前版本要求 iOS 13+。装旧版还要处理账号、验证、旧 IPA 签名，投入产出不划算。

### 死路三：Splashtop XDisplay / 各类老牌投屏

它们依赖 macOS 的内核扩展（kext）做屏幕输出。现在的 macOS 已经不再加载第三方 kext，SIP 下也装不上，等于整条路被系统封死。

### 死路四：AirPlay 接收端

macOS 可以当 AirPlay 接收器，但那是「把 Mac 当显示器」，方向反了；而且 iOS 12 的 AirPlay 镜像延迟高、画质差，还只能整屏镜像、不能当独立桌面。

## 转折点：usbmux 是可以被打洞的

真正让这件事成立的是一个很老的事实：**iOS 设备和 Mac 之间那条 USB 通道（usbmux）允许在设备上任意本地端口和 Mac 之间做端口转发**。Xcode 调试、iTunes 同步、`iproxy` 都是靠它。

也就是说，只要设备上有一个进程在监听某个端口，Mac 就一定能通过 USB 连上它——不需要开发者证书授权，也不需要特殊权限。

所以方案变成：

1. 自己写一个 iOS App，让它监听 `12346`。
2. Mac 通过 usbmux 连上去。
3. 在这条通道上跑自己的协议。

验证第一步时特意避开了 `12345`（常年被各种调试工具占着，第一次测试就被一个探测 App 抢了端口，连上了却收到别人的数据）。换到 `12346` 之后，第一次握手回了 `ACK:hello-usb`，链路成立。

## 画面怎么过去

按「谁最会干活就让谁干」的原则分配：

| 环节 | 用的东西 | 为什么 |
| --- | --- | --- |
| 造一块屏 | `CGVirtualDisplay`（私有） | 只有它能不装驱动就注册一块真显示器，窗口能拖过去、分辨率能切 |
| 采画面 | `ScreenCaptureKit` | 系统级采集，按显示器 ID 采，能直接指定像素尺寸 |
| 编码 | `VideoToolbox` | 硬件编码器，H.264、无 B 帧，延迟可控 |
| 传 | usbmux 裸 TCP | 走 USB，带宽稳定，不受 Wi-Fi 干扰 |
| 显示 | `AVSampleBufferDisplayLayer` | 直接吃 CMSampleBuffer，硬解，比自己写 OpenGL 简单得多 |
| 触控 | `CGEvent` | 把 iPad 的触摸点换算成 mac 上的鼠标事件 |

第一版跑通时的参数是 2048×1536 @30fps，码率 150–250 KB/s，动态画面峰值 2 MB/s。USB 2.0 的 480 Mbps 完全喂得饱。

## 踩过的两个真坑

### 1. 端口被占

第一次连上后收到的不是自己 App 的数据。查下来 `12345` 被另一个常驻的调试 App 占着，usbmux 照样能连上——连上的是别人。

**教训**：隧道能通 ≠ 对面是自己的进程。握手要做校验（现在用 `config` 包和画面尺寸隐式校验，出问题时日志会立刻暴露）。

### 2. 触控坐标恒为 0

现象很迷惑：iPad 上点哪儿，Mac 上都跳到屏幕左上角，还会点到 Apple 菜单。

原因在协议解析：触控包是 `8 字节头 + 9 字节负载`，Mac 端却按「裸 9 字节」在读，于是每次读到的都是从包头开始的错位数据，`x`/`y` 解析出来恒为 0。

**教训**：双向协议一定要共用同一套分帧代码；读循环必须按头里的 `length` 切包，不能假设「一次 read 正好一个包」。

## 从原型到工具

原型能跑之后，为了能分享出去，又做了几件事：

- **去掉 BetterDisplay**：原型阶段借它的虚拟屏省事，但让用户为了一个功能装另一个 App 不合理。改用 `CGVirtualDisplay` 自己造屏之后，BetterDisplay 就不需要了。
- **去掉 iproxy / libimobiledevice**：自己实现了 usbmux 客户端（`ListDevices` + `Connect`）。用户不用装 Homebrew，双击就能用。
- **GUI**：设备列表、权限引导、分辨率/刷新率/码率、实时帧率与流量、日志。
- **图标**：iPad 端和 Mac 端共用同一张手绘 SVG（青发女孩从带光标的屏幕后探头）。

## 关于「私有 API」

`CGVirtualDisplay` 是私有类，用 `NSClassFromString` + `objc_msgSend` 调用的。这意味着：

- 它不会通过 App Store 审核（本项目也不打算上架）。
- 系统更新可能改签名（本项目在 macOS 27 上验证过；早期实现里 `initWithWidth:height:refreshRate:` 是实例方法，被误当类方法调用时就会失败）。
- 但这部分完全不涉及系统完整性，不装驱动、不改系统文件、不需要关 SIP。

如果你介意私有 API，可以退回 BetterDisplay 建虚拟屏的流程（本项目早期版本就是这么跑的），只是要多装一个 App。

## 还能往哪走

- 键盘输入：`GCKeyboard` 或自定义输入法通道，两边都要加。
- 剪贴板同步：走同一隧道加一种消息类型即可。
- Apple Pencil：`UITouch` 的 `force`/`azimuth` 已经在手上，缺的是 Mac 侧的绘图事件注入。
- 自适应分辨率：让 iPad 在上线时先报自己的屏幕尺寸，Mac 自动选虚拟屏参数，就不用写死 2048×1536 了。
